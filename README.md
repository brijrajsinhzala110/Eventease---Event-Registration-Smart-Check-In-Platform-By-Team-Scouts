## Introduction

### 1. The Problem
Colleges often manage events with paper lists and spreadsheets. There is no limit on how many people can join. Students don't know if they got a spot. Entry checks are done by hand. Organizers can't see who has arrived.

↓

### 2. Event Publishing
Organizers add an event. They set the place, the time, the number of seats, the last day to sign up, and an optional picture.

↓

### 3. Registration
Students sign up for events. When seats run out, new students go on a waiting list. Each student can sign up only once for the same event. Nobody can sign up after the deadline.

↓

### 4. Tickets
After signing up, each student gets a QR code ticket. The ticket shows the event name, the student's name, and whether the ticket is valid.

↓

### 5. Check-in
At the entrance, the organizer scans the student's QR code. If it's valid, the student is let in. If the same code is scanned again, the app says "Already checked in."

↓

### 6. Live Attendance
Organizers can see how many people signed up for each event and how many have arrived. They can also see the full list of attendees.

↓

### 7. Admin
The admin can see the total number of users, events, and sign-ups. The admin can also see the list of all users and their roles.

↓

### 8. Future Scope
- **Cancel and move up:** Students can cancel a sign-up, and the next person on the waiting list gets the spot automatically.
- **Emails:** Students get emails when they sign up, move off the waiting list, or are reminded before the event.
- **Check-in without internet:** The scanner keeps working at venues with weak signal and syncs when the connection returns.
- **Reports:** Organizers can download attendance and sign-up lists as Excel or PDF files.
- **Stronger tickets:** QR codes are signed, so fake tickets can't be made.
- **College login:** Students sign in with their college account instead of a new password.
- **Paid events:** Events can charge a fee through online payment.
